# LumbarOS V1 系统架构

本轮代码由 Python 本地服务与无构建依赖的网页组成。启动时运行模拟设备，浏览器展示状态、记录与回放；真实传感器和执行器通过各自的适配接口接入。

## 模块分工

| 层 | 实现 | 作用 |
| --- | --- | --- |
| 启动与扩展 | [run.py](../run.py) | 启动本机服务，按显式参数加载执行器工厂 |
| 传感输入 | [devices.py](../lumbar/devices.py) | 串口 JSON 校验、帧顺序、矩阵到八区聚合、电脑端空载归零 |
| 场景模拟 | [simulation.py](../lumbar/simulation.py) | 模拟人体场景、腰托位置及其对接触信号的影响 |
| 反馈决策 | [controller.py](../lumbar/controller.py) | 个人参考、区间与局部判断、持续时间、滞回、动作与暂停 |
| 动作派发 | [actuators.py](../lumbar/actuators.py) | 统一命令、去重、剩余时限、停止、发送与确认状态 |
| 服务编排 | [service.py](../lumbar/service.py) | 约 20 Hz 主循环，操作顺序、故障、会话记录与状态汇总 |
| HTTP | [server.py](../lumbar/server.py) | 本机页面与 API |
| 界面 | [web/](../web/) | 八区、矩阵、曲线、控制、反馈、记录列表与回放 |

## 一次调节的过程

1. 新帧通过格式、顺序与新鲜度检查，按配置聚合区域信号。
2. 控制器结合当前个人参考与状态，判断保持、前顶、回退或停止。
3. 派发器将一次动作交给适配器，重复刷新不会延长原定动作期限。
4. 模拟适配器改变模拟位置；真实适配器需要由硬件接手方实现对应协议。
5. 输入、决策、派发与体验反馈进入会话记录；后续新帧继续参与判断。

个人参考来自使用者认可状态下约 3 秒的稳定采集，保存八区均值及波动。控制器以 5、6、7 区的平均接触为主要指标，同时检查局部偏强；1–4 区用于入座判断，8 区用于展示与记录。一个执行自由度驱动整块腰托前后运动。

当前方法为**个人参考驱动的带滞回区间反馈与状态机**。反馈按钮保存用户体验事件，供后续分析；本轮代码没有训练模型或自动修改参考。

## 两条设备路径

| 模式 | 输入 | 动作输出 | 当前状态 |
| --- | --- | --- | --- |
| 模拟 | 模拟八区数据与场景 | SimulationActuator | 可直接运行完整软件闭环 |
| 真实传感 | 16×16 JSON 串口帧 | 默认 DisabledActuator | 矩阵接入代码具备；八区需实测配置 |
| 真实执行 | 由传感路径提供接触数据 | 注入自定义适配器 | 模板待实现，协议与实物反馈需联调 |

`config/zones.json` 的八区索引保留为空。实际布面方向、索引和接触区域确定后，按[硬件说明](hardware.md)填写。当前固件提供传感采集；电机驱动、板端限时、限位、异步故障与位置反馈属于接手方实现内容。

`sent` 和 `acknowledged` 分别表示发送与接收确认，不能替代实际机械位置或动作完成反馈。真实模式的位置字段尚为 `null`，速度参数也需要按实物换算。

## 记录与回放

主机消费最新传感帧，保存消费到的输入、参考、参数、动作及事件。设备采样更快时中间帧可能被覆盖；记录不是无损的全速阵列采集。

进入回放先暂停实时自动，之后播放、拖动历史帧仅更新显示；返回实时后仍需明确开启自动。界面保留 LumbarLab 名称，作为本项目的实验台。
